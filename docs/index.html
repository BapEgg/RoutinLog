기술을 고른 이유

이름보다, 하는 일을 먼저 보세요.

앱과 서버는 같은 Kotlin을 쓰지만 서로 다른 프로그램입니다.

Kotlin + Compose

Android 화면

휴대폰의 화면과 버튼을 만드는 언어·도구입니다.

선택 이유: Android 권한·키보드·접근성 기능과 연결하기 좋습니다.

예: 체중을 수정하면 해당 화면의 숫자와 오류 안내가 함께 바뀝니다.

Spring Boot

서버

요청을 받고 검증·계산·저장을 처리하는 기반입니다.

선택 이유: 인증·DB 처리·운영 상태 확인을 한 프로그램에서 시작합니다.

예: 사용자 A의 요청으로 사용자 B의 기록을 읽지 못하게 합니다.

PostgreSQL + Flyway

데이터·변경 이력

관계가 있는 기록을 보관하고, 보관 구조의 변경을 관리합니다.

선택 이유: 날짜별 기록·계획 버전·중복 금지를 일관되게 다룹니다.

예: 같은 날짜의 체중을 두 번 저장해도 두 건으로 쌓이지 않게 설계합니다.

Docker + GitHub Actions

개발·자동 검증

같은 DB 실행 환경을 만들고, 코드를 바꿀 때 검사를 반복합니다.

선택 이유: 내 PC에서만 되는 문제를 줄이고 실패를 빨리 확인합니다.

예: 코드 반영 후 서버 테스트와 Android 빌드를 자동 실행합니다.

기록의 의미가 바뀌지 않도록.

계획 ≠ 실제 기록

다음 주 계획을 수정해도, 지난주 실제로 먹고 운동한 기록은 유지합니다.

정보 없음 ≠ 0

단백질 값이 없으면 미확인입니다. 먹지 않았거나 0g인 기록과 구분합니다.

AI 제안 ≠ 자동 적용

최종 결정은 사용자에게 있습니다. 부족 칼로리를 다음 주에 몰아서 채우지 않습니다.

계산·개인정보·기록 보존의 세부 기준
  • 영양 계산은 원본 기준량과 실제 섭취 g의 비율을 코드로 계산합니다. 예: 80g당 160kcal → 120g 섭취 시 240kcal. 원본과 계산 버전을 보존합니다.
  • 제품 정보나 기본 계획을 수정해도 과거 실제 기록의 스냅샷을 조용히 바꾸지 않습니다. 누락된 기록과 영양정보가 없는 기록도 구분합니다.
  • 걸음 누적값은 다시 읽을 때 덧셈하지 않으며, 휴대폰과 워치의 중복을 처리합니다. 소비 열량을 식사 목표에 자동 가산하지 않습니다.
  • 온라인 전용입니다. 서버 응답을 받지 못하면 저장 완료라고 표시하지 않고, 같은 저장 요청을 다시 보내도 중복 기록이 생기지 않게 구현합니다.
  • 로그에 인증 토큰·신체값·식단·자유 메모를 통째로 남기지 않습니다. 계정 삭제는 접근 차단과 원본·사진·리포트·추천 삭제까지 포함하는 후속 기능입니다.
  • 체중 변화는 기록에서 보인 관계로 설명합니다. 특정 식사·운동이 원인이라고 단정하거나 의료 진단으로 표현하지 않습니다.

시안의 초기 영양 목표·운동 정책은 과학적 검토를 마친 출시 정책이 아닙니다. Google·건강 데이터·AI·OCR·사진 보관의 실제 권한과 개인정보 조건은 기능 연결 때 확정합니다.

앱과 서버를 나눴기 때문에 Android SDK가 없어도 서버를 개발·테스트할 수 있습니다. 아래 명령은 별도 표시가 없으면 저장소 루트에서 실행합니다.

1. PostgreSQL과 서버 실행하기

처음 한 번 .env.example을 복사하고 POSTGRES_PASSWORD를 본인 로컬 비밀번호로 바꿉니다. 이미 .env가 있으면 복사하지 않습니다.

Copy-Item .env.example .env
# .env의 POSTGRES_PASSWORD를 변경한 뒤 실행
docker compose up -d postgres

$env:DB_URL = 'jdbc:postgresql://127.0.0.1:5432/routinlog'
$env:DB_USERNAME = 'routinlog'
$env:DB_PASSWORD = 'YOUR_LOCAL_DB_PASSWORD'
.\server\gradlew.bat -p server bootRun

YOUR_LOCAL_DB_PASSWORD는 예시 자리입니다. .env에 지정한 비밀번호와 같게 바꿉니다. DB 이름·사용자를 바꿨다면 URL과 사용자도 맞춥니다.

Docker Compose는 .env를 읽고, Spring Boot에는 DB_* 환경변수를 따로 전달합니다. 비밀번호가 포함된 .env는 Git에 올리지 않습니다. 개발 서버·DB는 기본적으로 PC 내부에만 열립니다.

다른 터미널에서 상태 확인

Invoke-RestMethod http://127.0.0.1:8080/actuator/health
Invoke-RestMethod http://127.0.0.1:8080/api/v1/system/status

정상 상태는 health의 UP와 아래 형태의 응답입니다. 버전은 실제 빌드값이며, ready가 앱 출시 준비나 로그인 성공을 뜻하지는 않습니다. 그 외 개인 API는 인증 구현 전까지 기본 차단합니다.

{"service":"routinlog","status":"ready","version":"0.0.1-SNAPSHOT"}

종료는 서버 터미널에서 Ctrl+C, DB는 docker compose stop입니다. 일반 종료에 DB 볼륨 삭제 명령을 사용하지 않습니다.

2. Android 앱 빌드하고 서버 연결 확인하기

Android Studio에서 android/를 열고 SDK Platform 36과 Build Tools 36.0.0을 준비합니다. 개인 SDK 경로는 android/local.properties 또는 ANDROID_HOME에 두며 저장소에 올리지 않습니다.

.\android\gradlew.bat -p android :app:assembleDebug :app:testDebugUnitTest :app:lintDebug

APK는 android/app/build/outputs/apk/debug/에서 확인합니다. 에뮬레이터의 기본 서버 주소는 PC를 가리키는 http://10.0.2.2:8080/입니다.

서버를 실행한 상태에서 시작 화면의 개발 연결 확인을 누르면 실제 상태 요청을 보냅니다. 샘플 체험의 체중·허리는 이 요청에 포함하지 않습니다.

USB로 연결한 실제 기기에서 개발 서버를 쓸 때

adb reverse tcp:8080 tcp:8080
.\android\gradlew.bat -p android :app:installDebug -Proutinlog.debugApiBaseUrl=http://localhost:8080/

기기를 개발용으로 연결·승인한 뒤 실행합니다. HTTP 예외는 Debug의 에뮬레이터·localhost에만 허용하며, 다른 개발 주소는 HTTPS를 사용합니다.

현재 앱의 샘플은 메모리에만 있습니다. 화면 회전 중에는 입력을 유지하지만 체험 종료·프로세스 종료 시 초기화됩니다. 실제 로그인·저장·식단·운동 편집·건강 연동은 아직 제공하지 않습니다.
3. 테스트 결과를 확인하고 한계를 구분하기
.\server\gradlew.bat -p server test bootJar
.\android\gradlew.bat -p android :app:testDebugUnitTest :app:lintDebug

서버 실행 JAR는 server/build/libs/, 서버 테스트 보고서는 server/build/reports/tests/test/index.html에 생성됩니다.

  • 서버 19개 테스트는 영양 비례 계산·null·범위, 보안 접근 차단, Flyway 스키마·JPA 매핑과 제약을 확인합니다.
  • 서버의 로컬 자동 테스트 DB는 H2의 PostgreSQL 호환 모드입니다. 실제 PostgreSQL에서의 기동·마이그레이션 검증은 별도입니다.
  • Android 입력 테스트 7개는 null, 빈 입력, 잘못된 숫자·정밀도, 소수점 쉼표·날짜, 상한 포함과 초과를 확인합니다.
  • 체중 1,000kg·허리 500cm의 상한은 서버 저장 범위와 맞춘 기술적 제한이며 의학적 권고가 아닙니다.
  • 자동 검사 통과와 실제 기기 사용성 검증은 다릅니다. TalkBack·큰 글씨·키보드·뒤로가기·통신 실패·백그라운드 복귀·배터리를 따로 확인합니다.

최신 성공·실패·미확인 상태는 이 페이지 상단과 검증 기록을 봅니다. CI 파일 작성과 원격 CI 실행 통과도 구분합니다.

4. 운영 앱·스토어 배포 전 필요한 설정
  • 임시 앱 식별자는 com.bapegg.routinlog입니다. Google Play 최초 등록과 OAuth 클라이언트 생성 전에 소유자가 확정합니다.
  • Release에는 가짜 운영 주소가 없습니다. routinlog.apiBaseUrl 또는 ROUTINLOG_API_BASE_URL로 실제 HTTPS 기본 주소를 설정해야 사전 빌드 검사를 통과합니다.
  • 기본 주소는 끝 /가 필요하며 사용자정보·쿼리·fragment를 넣지 않습니다. Release는 HTTP를 허용하지 않습니다.
  • 실제 Google 설정, 서명키, 운영 API와 개인정보·삭제·지원 안내, 스토어 테스트·심사가 별도로 필요합니다. API 키·서명키·토큰을 소스에 넣지 않습니다.
  • 클라우드·AI·OCR 제공자와 비용·계약 조건은 연결 단계에 확정합니다. 구조도에 있는 S3·AI가 현재 배포되었다는 뜻은 아닙니다.

빌드나 첫 Git 푸시가 성공해도 아직 샘플 체험 단계라면 출시 완성본이 아닙니다. 미완성 기능을 실제 서비스 기능으로 소개하지 않습니다.

디자인 시안·폰트·이미지의 사용 범위

디자인 기준 시안은 2026년 9월 30일 보존한 67개 HTML 화면입니다. 같은 폴더의 assets와 함께 열며 실제 Android 앱이나 서버 연동 화면은 아닙니다.

  • 실버 배경·차콜 카드·짙은 블루 실행 버튼·은은한 연두 선택/완료·빨강 오류를 앱에 옮깁니다.
  • 과거 시안의 Naver·iOS 설명은 현재 구현 범위가 아닙니다. 현재 기준은 Android·Google·온라인 기록입니다.
  • 가상 날짜·수치를 실제 기록으로 초기화하지 않습니다. 제품 사진·검수 운동 영상·3D 모델도 시안으로 확보된 것이 아닙니다.
  • Android 폰트는 현재 시스템 sans-serif입니다. 웹용 SUIT woff2를 Android 폰트로 사용하지 않으며, 추후 TTF/OTF와 라이선스를 확인합니다.
  • 웹 시안 자산의 SUIT 라이선스와 Lucide 라이선스를 함께 보존합니다.

이 안내서는 외부 폰트·CDN·이미지를 불러오지 않으며 시스템 글꼴과 자체 SVG를 사용합니다. 인터넷이 없어도 파일을 브라우저에서 열어 읽을 수 있습니다.
